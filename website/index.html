the shift

Agents should feel like infrastructure, not a tab you babysit.

Two mental-model shifts — they're the whole point of paw.

npm run dev→docker compose up -d

Stable, not supervised.

Raw claude is npm run dev — a foreground process in a terminal tab. You watch it, you kill it, it dies with your session.

paw is up -d: agents run warm and detached, persistent for weeks, resuming themselves on next contact and replaying anything they missed. You stop managing them — they start feeling like a service that's just there.

Express→Next.js

The filesystem is the router.

Express makes you wire every route by hand. Next.js made the file path the route — drop a file, the endpoint exists.

paw does that for background agents: a folder is the address. paw chat ~/some/repo — the path resolves to the agent, no ids to track, no registry to wire. File-system routing on top of warm agents.

paw adopt

Your past sessions, back on the mesh.

A session you ran in a plain terminal can't be messaged — it's not on the mesh. adopt re-files it as the folder's agent with a resume: pin, so the next spawn launches with full history and rejoins the conversation.

  1. 1

    Find the session

    paw sessions ~/repo lists every transcript — id, when, first message, and the «name» if you ran claude --session-name or /rename.

  2. 2

    Adopt it

    paw adopt ~/repo --resume my-debug takes a transcript id or a named session. It verifies the recorded cwd matches the folder, then spawns it live.

  3. 3

    It picks a name

    Named session → @my-debug. Otherwise the folder basename → @repo. Chosen at first adopt, reused after.

  4. 4

    Two-writer safe

    If that session is still open in a standalone claude, adopt refuses and names the pid to kill first — two writers corrupt one transcript. --force overrides.

$ paw sessions ~/repo

$ paw adopt ~/repo --resume my-debug

paw chat

The headline: a room your repos live in.

Join the mesh as a persistent peer named "you" — so agents have somewhere to reply. With no arg you start in broadcast mode; the moment you @name someone they become your sticky target and plain lines DM them.

  1. @

    Sticky targets

    @name <msg> DMs that peer and latches it. Plain lines keep going there until you @ someone else. Tab-completes from the live roster.

  2. #

    Broadcast

    #general <msg> always multicasts to a channel — every agent in the room hears it.

  3. ↺

    Wakes exited agents

    @-mention a known-but-offline agent and paw respawns it, resumed. Messages sent while it slept replay from its durable inbox.

  4. ⌁

    Live round-trips

    After a DM: ⏳ waiting…, then ✓ picked it up when the agent starts, then the reply stamped with its round-trip time. /who, /ps, /dm on tap.

paw dm · inbox · mailbox

Or hand it off and walk away.

paw chat is the live conversation. paw dm is its fire-and-forget twin: give an agent a task, leave, and collect the reply — a PR, a result, a question — from paw inbox whenever you're back.

  1. →

    Fire and forget

    paw dm ~/repo "<task>" sends and returns instantly — no terminal to hold. For a live back-and-forth, that's paw chat.

  2. 📬

    The mailbox keeps you reachable

    An agent can only reply to a peer it can resolve on the mesh. A tiny mailbox daemon auto-starts and holds you present permanently — so a reply minutes later lands in your durable inbox. It never reads your mail; that's paw inbox's job.

  3. 📥

    Collect replies

    paw inbox shows what's new since last time; --history shows the backlog. A pure reader — it never competes with a live paw chat for your inbox.

  4. 🤝

    Even agents that aren't yours

    Point a DM at a teammate's agent; the reply comes back to your inbox. No shared terminal, no babysitting.

paw dm / inbox
$ paw dm ~/repo "rebase onto main, fix conflicts, run tests"
→ repo: rebase onto main, fix conflicts, run tests
sent → read replies with `paw inbox`

commands

Two verbs birth, two verbs interact.

create a fresh agent or adopt a resumed one; chat in messages or open its terminal.

paw chat [folder|name|repo@branch]
The headline. Join the mesh as a persistent peer, spawn/focus an agent, DM it. Replies stream back live.
paw adopt [folder] --resume <id|name>
Bring a past claude session back as a live mesh agent in one step — resumed, with full history.
paw create [folder|repo@branch]
Spawn a fresh warm agent (no resume), without entering the REPL. The pair of adopt.
paw open [folder|name]
Attach to the agent's live terminal — its pty. Spawns it first if absent. paw attach is an alias.
paw dm <name|folder> "<msg>"
Fire-and-forget. Hand an agent a task and walk away; read replies with paw inbox. Sent as you, so the reply is deliverable. For a live back-and-forth use paw chat.
paw inbox [--history] [--limit N]
Read your DM inbox — new since last time; --history for the recent backlog. A pure reader; never competes with a live chat.
paw log [folder|name] [--tail N] [--follow]
Read an agent's session transcript directly — its turns + tool calls — without attaching or messaging. Read-only; --follow tails live.
paw sessions [folder|repo|repo@branch]
List a folder's claude transcripts. A repo lists every git worktree + the sessions inside each.
paw ps · paw stop <name> · paw down
List live agents · stop one · tear down the daemons paw started (mesh · manager · mailbox).

<repo>@<branch> resolves to the worktree that has that branch checked out — across chat, open, adopt, and sessions. It resolves an existing worktree and fails loud if it's missing; it never auto-creates one.

how it works

A durable bus between you and your folders.

A folder maps to a stable agent name. cotal carries presence, DMs, and channels over a NATS + JetStream mesh — plus a durable inbox: messages sent while an agent is offline queue and replay on its next spawn. Agents run warm under a pty runtime, live across days, resuming in place.

🐾 Agents act unattended on your repos.

By default they run with --permission-mode bypassPermissions and auto-spawn when you chat / open / adopt — an agent can edit and run code in its folder without prompting. Scope is your own machine. Tighten with PAW_PERMISSION and confine reachable folders with PAW_ROOT.
